# 赛季末副角色活动查询

2026-10-29北京时间18:29上线。用户验收真实数据图片后明确回复“可以上线”，按最新生产代码加入本次独立命令。

独立命令 `#bz 副角色`，英文别名 `#bz secondary`。群聊、私聊均返回图片；不增加播报或订阅，不改网站与职业概况。

- `#bz 副角色`：八职业概览，每个主角色列出选取率前三的副角色。
- `#bz 副角色 杜利`：该主角色的全部七种副角色排行。
- `#bz 副角色 杜利 胜率`：按10胜率排序，保持相同分母。
- `#bz 副角色 胜率`：八职业按10胜率取前三。支持既有英雄中英文、中文别名，例如 `工程师`、`The Dragons`。

## 活动与样本口径

活动单独使用 `plugins/bazaar_plugin/secondary_hero_event.json`，不读取随补丁修改的 `CURRENT_PHASE`。目前限定赛季19、版本19.4，起点沿用已核对的19.4数据起点：北京时间2026-10-29 00:00。用户确认结束时间为下周四0点，换算为北京时间2026-11-05 00:00，即UTC 2026-11-04 16:00。

开始时间包含、结束时间不包含；活动中查询不计未来时间记录。时间字段沿用采集器的 `created_at`，不声称它等同于游戏实际开局时间。没有活动候选曝光记录，因此选取率只表示已记录选择分布，不是三选一给到某选项时被选择的概率。

按原始19.4 GameData的八个传奇技能ID识别。普通同名技能、技能位置、物品及品质都不用于推断。同局重复出现同一技能只计一次；缺失、JSON损坏、出现多个不同副角色技能、出现主角色自己的对应技能均不猜测。每张图公开识别覆盖率、未识别和冲突场次。

- 选取率 = 该副角色场次 / 同主角色有效识别场次。
- 10胜率 = 该搭配 `stat_wins >= 10` 场次 / 该搭配场次。
- 默认 `min_wins=1`，图片明确标注“已收录1胜及以上样本”。现有采集器默认不入库0胜局，本功能没有改变采集范围。只有确认数据源含0胜后才应设置为0；更改配置不会回填历史。
- 所有段位都参与；排除未知主角色、负数/非整数/缺失胜场、其他活动范围和无效时间戳。
- 同一主角色内按未舍入选取次数或精确分数的10胜率排序；并列时场次多者优先，再按英文标识稳定排序。
- 少于30场标记“小样本”；无该搭配样本时10胜率为横线，不虚构0%；无有效样本时选取率也为横线。总体10胜率按有效对局加权。

## 历史数据保留

活动结束后命令继续可用，图片自动标记“活动已结束 · 历史数据”，时间上界固定为结束时间。注意：现有赛段更新会把在线对局库归档到COS并清空，因此仅保留命令代码不足以保留可查询数据。

本命令支持独立数据源 `BAZAAR_SECONDARY_RUNS_DB_PATH`，优先于通用 `RUNS_DB_PATH`。活动收尾时需要保留完整活动库（SQLite在线备份，或下载完整已归档库），将这个变量指向保留库，再验证冻结后的八职业计数。若下一版更新先于活动结束，需先明确是否仍有活动，更新活动版本范围并保留各阶段数据；不得默默将其他版本混入。当前固定19.4。

本次上线了命令与活动配置，没有变更生产环境变量、另存完整生产活动数据库、向QQ发送测试消息或创建定时任务。活动结束时保留完整历史库并切换数据源，仍属于未来的收尾操作；未创建提醒。

## 查询与发送

SQL聚合使用独立只读连接，线程内打开和关闭，保留 `mode=ro`、`query_only` 和12秒执行预算。不会因路径错误新建空对局库，不加载全量技能记录到Python。查询和渲染在工作线程执行；服务锁合并并发查询，60秒复用统计。同一快照最多缓存18种图片（八角色与概览，各两种排序），保存上传字节后移除临时PNG。

图片尺寸：单角色1080×1660、八职业概览1080×2080。复用现有本地英雄头像，缺图显示占位。图片生成失败保留完整文字结果。QQ明确拒绝时返回文字，网络异常/超时时不重复发送，以免双发。所有本地验证使用模拟QQ接口。

命令所需的时区转换、头像索引及QQ返回值检查由副角色模块自行提供；八位英雄头像及来源说明随本次提交一起保存。它不依赖尚未合入主分支的职业播报模块，因此从主分支新建的干净检出也能直接运行。
