2026-10-26 北京时间 18:53 发布。视觉已用 Koucha_、Hyx499 的真实数据验收，用户随后明确授权上线。测试名单只用于本地图片预览，没有加入实际 QQ 群订阅。

## 指令与展示

- `#bz watch <用户名>`：检查玩家及当前赛季统计，发送订阅结果图。大小写不同的同名玩家不重复订阅；新增记录保留输入大小写。
- `#bz unwatch <用户名>`：取消订阅结果图。
- `#bz watchlist`：查询本群名单并发送图片，每页最多 6 人。单个玩家查询失败仍保留名单和其他玩家数据。
- `#bz testpush`：仅现有管理员可用，给当前群发送带“测试预览”标记的战报，不记入正式日报发送记录。
- 日报每页 1 位玩家，所有页面统一为 1080 × 1305 像素，沿用已验收的分数、排名和趋势布局。全群计数出现在每一页，页脚标明页码。其他订阅图片也统一为 1080 像素宽。
- 空名单、重复订阅、取消、权限及查询错误均使用状态图；渲染失败时保留文字兜底。

## 统计与调度

每天按北京时间前一日 10:00 至当日 10:00 计算。取起止时刻之前最近的有效记录，不引用截止之后的数据。无新增记录、无赛季记录、缺少基线和查询失败分别展示，不当作零涨跌。

`watch_cards.py` 提供共用统计和渲染代码；`watch_service.py` 组织查询、分页和发送；插件指令及定时任务复用这一服务。赛季沿用 `data_client.py` 中的当前赛季及 API 编号映射。

框架每 60 秒触发检查；插件加载阶段只注册任务及官方启动、心跳事件处理器，在客户端事件回调中绑定持久事件循环并启动后台初始化。调度器在线程中运行，通过 `run_coroutine_threadsafe` 转交已绑定的客户端事件循环，避免跨事件循环共享查询/渲染限流器及 QQ API。不能在 `on_load` 内捕获循环：当前框架在工作线程中加载插件，随后会关闭该临时循环。服务用显式 UTC+8 判断，只有北京时间 10:00 至 10:59 会处理当日日报。客户端事件循环就绪时也检查一次，支持该时段内重启续发；11:00 后不自动补发旧日报，可由管理员测试推送查看。跨群玩家按大小写无关身份去重，每轮最多 3 个并发查询。超时或网络连接错误重试一次。

## 订阅迁移与发送恢复

首次访问存储时，将原 `plugins/bazaar_plugin/cache/subscriptions.json` 导入同目录 `subscriptions.sqlite3`，原 JSON 保留。迁移和订阅修改使用事务；坏 JSON 会报错，不会静默清空。正式部署前需备份两份存储文件。导入后 SQLite 是实际数据源，回滚到旧版时不能直接将过时 JSON 当作最新订阅。

发送记录按群、赛季、截止日期和页码保存，第一次生成时冻结该次的图片页和对应兜底文字；当天名单后续变更不重排已发送页面。成功页跳过，失败页至少间隔 60 秒重试，最多 3 次，前页未完成时不继续后页。

如果进程在发送中断开，无法判断 QQ 是否已经收到了该页，该页会保留 `sending` 状态并写日志，不盲目自动重发。管理员核实后可用测试推送补看。QQ 发送确认和本地数据库不在同一事务中，因此不承诺绝对恰好一次投递；明确返回发送错误后的重试也可能存在确认不一致的边界情况。

图片输出位于 `data/charts/watch/`。正式日报续发依赖已保存图片；应至少保留当日图片。图片丢失时发送该页对应的文字兜底。
